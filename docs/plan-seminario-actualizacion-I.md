# Seminario de Actualizacion Tecnologica I

## Proyecto integrador

Sistema web para apoyar la gestion y consulta de rutas, vehiculos, horarios y novedades del servicio de recoleccion de residuos.

El producto de Seminario I sera una plataforma web administrativa y de consulta basica. Seminario II podra retomar la API y evolucionarla hacia una aplicacion movil ciudadana.

## Alcance inicial

- Gestion de zonas, barrios o puntos de referencia.
- Gestion de vehiculos y conductores.
- Gestion de rutas y recorridos.
- Programacion de horarios.
- Registro del inicio de una ruta.
- Registro de novedades: retrasos, cambios o cancelaciones.
- Consulta estimada de paso por zona.
- Usuarios administrativos y operadores.
- API REST, base de datos y frontend web responsive.
- Ambientes de desarrollo, pruebas y produccion.

Quedan fuera de Seminario I: GPS en tiempo real, notificaciones push, aplicacion movil y algoritmos avanzados de optimizacion de rutas.

## Organizacion del trabajo

El curso trabajara con celulas verticales y equipos horizontales.

### Celulas verticales

Cada celula desarrolla un modulo funcional y debe participar en analisis, diseno, desarrollo, pruebas, documentacion e integracion.

### Equipos horizontales

- Arquitectura y backend.
- Datos y API.
- UX/UI y sistema de componentes.
- Calidad y testing.
- DevOps, Git y despliegue.
- Documentacion e IA aplicada.

Cada estudiante tendra una responsabilidad principal por rol, pero debera participar en las fases comunes y comprender el flujo completo del producto.

## Flujo de trabajo

1. Toda actividad debe tener una Issue.
2. Toda Issue debe indicar responsable, criterio de aceptacion y evidencia.
3. El trabajo se desarrolla en ramas.
4. La integracion se realiza mediante Pull Request.
5. Ningun cambio llega a `main` sin revision.
6. Las decisiones transversales se documentan.
7. GitHub registra el codigo y el proceso; Teams conserva reuniones y evidencias audiovisuales; Moodle recibe las entregas formales.

## Evaluacion

- Entrega 1: problema validado, alcance, roles, UX/UI y arquitectura inicial. 30%.
- Entrega 2: backend, base de datos, API, frontend integrado y avance funcional. 30%.
- Entrega 3: producto publicado, testing, documentacion y defensa tecnica. 40%.

La actividad integradora de cada entrega funciona como evidencia tipo parcial dentro del proceso acumulativo. Al cerrar cada corte se consolida la calificacion y no se trasladan actividades ordinarias pendientes a cortes posteriores, salvo las condiciones institucionales de fuerza mayor.

## Actividades del estudiante

El trabajo independiente incluye investigacion conceptual, entrevistas y observacion, reuniones verticales de celula, reuniones horizontales de estandarizacion, desarrollo individual por rol, revisiones de codigo, pruebas, documentacion y preparacion de la defensa.

## Evidencias

- GitHub: Issues, commits, ramas, Pull Requests, documentos y versiones.
- Teams: reuniones clave, entrevistas autorizadas y acuerdos.
- Moodle: tres entregas formales.
- Trello o GitHub Projects: seguimiento del trabajo.
- Bitacora de IA: consultas, decisiones, codigo aceptado y rechazado.

## Resultado esperado

Un producto web basico pero tecnicamente completo, publicado en internet, con arquitectura comprensible, datos persistentes, API documentada, interfaz coherente, pruebas, trazabilidad del trabajo y posibilidad real de evolucion hacia una aplicacion movil en Seminario II.
